# Windows 98 experience

- Independent static v86 frontend in `public/`; default URL resumes the local Win98 snapshot, never cold-boots. `?author=1` (legacy `?install=1`) loads a QEMU-prepared whole raw disk (up to 1 GiB) using `install.js` / `Win98Disk` and bundled verified BIOS ROMs. Optional v86 state + v2 handover metadata must match disk/state/firmware/build hashes; restore stays paused. OS installer/blank-disk/floppy controls are removed. Never substitute synchronous authoring state into the matched async demo set. See `README.md`.
- `public/images/` contains the ignored user-authored synchronous master: `disk.img` (512 MiB), `state.bin` and v2 `handover.json`. Retained for authoring/rollback only. Active default is `images/published.json` → `publishing/win98-release-001/manifest.json`, compressed state (11.79 MiB) and lazy 256 KiB base chunks; tested real Windows restore. Default never downloads the retained raw master while the pointer is active. Old copy.sh OS assets and fetch script are removed. Replace the complete matched handover only, and test fresh restore.
- Normal development: use the normal webpage, mount software ISOs via VM-værktøjer, edit/install inside Windows, and restart via Windows' own Start → Shut Down → Restart (never page reload). Leave the desired visitor screen open, eject CD, then export **Eksporter publiceringsoverdragelse (.tar)**. All changes are session-only until export; reload/close loses unexported work. No mode switch or new `prepare` step is needed for routine updates.
- For an existing lazy publishing handover in `/tmp/`: run `node publish.cjs finalize /tmp/hal9k-windows98-publishing-handover.tar NEW_VERSION`, test fresh restore with `PUBLISHED_VERSION=NEW_VERSION make test-browser`, then `node publish.cjs activate NEW_VERSION`. Verify the normal page too; retain prior immutable version/source archives for rollback. Raw author mode is only for importing another QEMU disk or returning a merged disk to QEMU.
- `publish.cjs prepare RAW.tar VERSION` stages immutable async 256 KiB disk parts; `?publish=1` cold-boots the draft and exports async publishing capture with original base + overlays. `finalize CAPTURE.tar VERSION` validates/compresses it; test `?published=VERSION` then `activate VERSION`. `images/published.json` selects the active immutable version; no silent raw fallback after activation. Never pair async state with merged disk or synchronous authoring backend.
- CD source: `test-cd/` (`hal9k.exe`, `AUTORUN.INF`, text). Root `make assemble`/`make build` regenerate the ISO using `xorriso`, then embed all assets. Standalone dev: `make test-iso` after CD changes.
- Page auto-inserts the bundled ISO; Windows AutoRun launches HAL9K. Mount via ArrayBuffer, not async File-backed media (guest cannot read it with this v86 build).
- `public/app.js` owns pointer lock/Esc release, click-unlocked audio, aspect-preserving fullscreen, and public VM tools. Exports stay paused; synchronous snapshots include full disk contents. Raw authoring exports v2 synchronous handovers. Lazy default/draft exports async publishing captures with their own original base disk and overlays (never copy.sh OS assets). No signup API bridge yet.
- Startup overlay uses a Windows 98 segmented progress bar: real streamed compressed-state bytes/percentage, indeterminate preparation/verification/restore, hidden at ready/error. Respect reduced motion; never add artificial startup delays. `make test-loader-browser` tests paced real download progress and error cleanup.
- Checks: `make test`; Playwright `make test-browser`; `make test-tools-browser` also needs `xorriso`. Set `BASE_URL` and optionally `CHROMIUM_PATH`; root README explains `NODE_PATH` setup.
